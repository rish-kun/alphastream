## 2025-04-18 - Database-Level Deduplication is Safer than Python-Side
**Learning:** When queries use `.limit()` and subsequent Python-side deduplication (like `unique()` or custom loops), the result set can easily fall short of the requested limit if duplicates exist. Furthermore, joining 1-to-many relationships (like articles to stock mentions) naturally produces duplicate rows that have to be managed.
**Action:** Use `.where(parent.relationship.any(child.field.in_(...)))` to query 1-to-many relationships without producing duplicate root entities, eliminating the need for Python-side `.unique()` entirely. Use `.distinct(column)` with matching `.order_by()` to leverage PostgreSQL's `DISTINCT ON` for selecting the most recent record per group, rather than fetching all groups into Python memory.
