## 2024-05-02 - Use EXISTS over JOIN for Limit Queries
**Learning:** When combining SQL queries with relationship filters (e.g. `mentions`) and deduplication constraints, applying `.limit()` *after* a `.join()` but *before* Python-side `.unique()` deduplication results in overfetching and incorrect row counts if multiple relationships exist per row. Furthermore, avoiding duplicate rows in SQLAlchemy by using `.any()` or `.has()` instead of `.join()` generates an `EXISTS` subquery, completely bypassing the need for Python-side `.unique()` and preventing limit-related bugs.
**Action:** Always prefer using `.any()` or `.has()` on relationships when filtering data, especially when pagination or `.limit()` is involved, to avoid Python-side deduplication overhead and incorrect limit counts.
